Four names. Four different jobs.

The best name is not just available. It tells people how to understand the thing and gives the product a language of its own.

Homebrew

A package manager could have sounded like infrastructure. Homebrew made it human, native to hacker culture, and immediately generative.

brew, formula, cask, tap, keg, cellar

Automic Vault

A compact invented name for a security product that protects tools and credentials from automated actors. Serious, ownable, and product-shaped.

authority, automation, containment

Supermassive Book Hole

A ridiculous name for a delightful product. It makes the metaphor instant, creates a visual identity, and is nearly impossible to forget.

books go in, gravity does the rest

PromiseKit

Deliberately plain. It positions the framework as fundamental and borrows Apple's familiar Kit pattern so developers know where it belongs.

a foundational framework for Apple platforms

A name with somewhere to go.

Positioning is inside it.

The name should reduce the amount of explanation your product needs, not create a new explanation problem.

It sounds good aloud.

People have to recommend it, introduce it, search for it, and remember it later.

It creates language.

The strongest names make features, commands, campaigns, and future products easier to name too.
